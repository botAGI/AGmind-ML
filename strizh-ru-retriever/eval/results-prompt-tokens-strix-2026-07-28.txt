# Prompt tokens vs TTFT — почему TTFT различается между эмбеддерами (контрольный замер)
# ХАРНЕСС: eval/prompt_tokens_check.py (sha256:16 = 30bd37bfb561c4bc), корпус eval/corpus_ru.json
# date: 2026-07-28T10:54:19Z
# ЗАЧЕМ: в основном RAG-прогоне TTFT у STRIZH систематически выше, чем у bge-m3, хотя сам
#   эмбеддинг запроса у него в 9 раз быстрее. Гипотеза: модели извлекают разные чанки, а TTFT
#   включает prompt processing извлечённого контекста.
# ПОЧЕМУ НЕ СИМВОЛЫ: первый контроль (eval/context_len_check.py) мерил ДЛИНУ В СИМВОЛАХ и дал
#   +7.2% среднего у STRIZH, но по медиане попарной разности −44 символа (STRIZH длиннее лишь
#   в 3 запросах из 10). Прокси оказался негодным: корпус смешанный (русская проза + код + YAML),
#   и символов на токен у выборок разное — 2.84 у STRIZH против 3.05 у bge-m3.
#   Здесь берётся серверная метрика llama-server timings.prompt_n = фактические токены промпта.
# МЕТОД: та же цепочка (embed -> cosine top-8 -> rerank top-4 -> тот же шаблон prompt), запросы
#   идут ПОСЛЕДОВАТЕЛЬНО, конкуренции нет, поэтому TTFT здесь = чистый prefill без очереди.
#   10 запросов x 3 повтора на эмбеддер, n_predict 32, cache_prompt=false.
#
# РЕЗУЛЬТАТ
#   токены промпта   STRIZH медиана 1886 (среднее 1865, 1472-2175)
#                    bge-m3 медиана 1716 (среднее 1619.5, 712-1923)
#                    разница медиан +9.9%, средних +15.2%
#   попарно по 10 запросам: [53, 155, 117, 853, 259, 0, -247, 994, -153, 424]
#                    медиана попарной разности +136 токенов, STRIZH длиннее в 7 из 10
#                    (символьный прокси давал 3 из 10 — знак эффекта был перевёрнут)
#   TTFT одиночного потока  STRIZH 1973 мс, bge-m3 1825 мс (+8.1%)
#   связь: TTFT = 0.942 мс на токен промпта, R2 = 0.973 по 60 точкам ОБЕИХ моделей вместе
#          (обе ложатся на одну прямую: TTFT определяется числом токенов, а не тем, какой эмбеддер их выбрал)
#
# ЧЕГО ЗАМЕР НЕ ПОКАЗЫВАЕТ: в основном прогоне 4 потока делят 4 слота, и там разрыв TTFT больше
#   (148 мс здесь против ~1000 мс под нагрузкой) — под конкуренцией более длинный prefill
#   удлиняет ещё и ожидание соседних потоков. Раздельно вклад prefill и очереди не измерялся.
#   Содержание контекста у моделей тоже различается, не только длина; релевантность здесь не мерилась.
