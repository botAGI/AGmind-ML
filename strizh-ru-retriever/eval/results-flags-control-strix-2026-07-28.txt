# Контроль: объясняет ли асимметрия флагов серверов разрыв в индексации
# ХАРНЕСС: eval/batch_thr.py (sha256:16 = 2cd538885af735b6) и eval/index_load_check.py (sha256:16 = 6ac369bcd39bd296), входные данные eval/texts_long_ru.json, оркестратора нет
# date: 2026-07-28
# ПОВОД: в опубликованных прогонах embedding-серверы поднимались с РАЗНЫМИ флагами:
#   strizh  --pooling mean -ngl 999 -c 65536 -b 8192 -ub 8192 -np 8
#   bge-m3  --pooling cls  -ngl 999 -c 8192  -b 4096 -ub 4096 -np 8
#   Законный вопрос рецензента: не вызван ли разрыв в индексации вдвое меньшим batch/ubatch у bge?
# МЕТОД: eval/batch_thr.py, длинные чанки (eval/texts_long_ru.json, ~350 токенов),
#   12 батчей на точку, один и тот же хост и образ. bge пересоздан с флагами STRIZH.
#
# batch  bge -b4096 -ub4096   bge -b8192 -ub8192 -c65536   STRIZH -b8192 -ub8192
#   4         58.8 emb/s              43.1 emb/s                 476.4 emb/s
#  16         45.6 emb/s              39.8 emb/s                 510.1 emb/s
#
# ВЫВОД: выравнивание флагов НЕ помогает bge-m3, а ухудшает его результат (-27% на батче 4,
#   -13% на батче 16). То есть асимметрия в опубликованных прогонах играла В ПОЛЬЗУ bge,
#   и разрыв примерно в 10 раз объясняется размером модели, а не конфигурацией сервера.
#   (Почему больший ubatch вредит: у 568M-модели с 8192-контекстом растёт рабочий набор
#   на шаг, и на iGPU с общей памятью это не окупается. Отдельно этот механизм не проверялся.)

# ДОБАВЛЕНО ПОСЛЕ РЕВЬЮ: контроль выше НЕДОСТАТОЧЕН, потому что eval/batch_thr.py последователен.
#   При батче 4 в полёте ~1400 токенов, что влезает в один ubatch при ОБЕИХ конфигурациях, то есть
#   в этом режиме флаг -ub физически не может проявиться. А спорные прогоны шли под конкуренцией
#   (3 и 6 closed-loop воркеров, ~4200 и ~8400 токенов в полёте). Перемерено в том режиме:

#   конфигурация                                 воркеров   батчей/с   текстов/с   p95
#   bge-m3  -c 8192  -b 4096 -ub 4096 (штатно)       3        12.33       49.3    239.0 мс
#   bge-m3  -c 65536 -b 8192 -ub 8192 (как STRIZH)   3        12.33       49.3    239.9 мс
#   bge-m3  -c 8192  -b 4096 -ub 4096 (штатно)       6        11.64       46.6    517.7 мс
#   STRIZH  -c 65536 -b 8192 -ub 8192                3       229.24      917.0     15.1 мс

#   ВЫВОД: под конкуренцией флаги не меняют bge-m3 ВООБЩЕ (12.33 против 12.33 батча/с, до сотых),
